# P3b1 运行时与吞吐探测协议

总控于 2026-09-25 在测量前冻结。版本 `gd-runtime-probe-v1`。本包只选择后续工程验证的设备方向，不是正式训练预算、棋力评测、模型晋级或 P3 整体验收。沿用 P1/P2/P3a 算法源码，新增独立基准入口；不修改规则、不覆盖历史候选。

## 环境与数值

隔离 `.venv` 使用 Python 3.13.5、PyTorch 2.9.1+cu128（官方 CUDA 12.8 wheel），以与既有 2.9.1+cpu 尽量保持版本可比。不是追逐最新版本。记录安装清单、GPU/驱动、CUDA runtime、capability、编译架构、Python 与线程数；是否支持以实际前后向执行为准。现有全局 CPU Python 保留。

模型为原 DMCNetwork，float32，初始化 seed 271828，torch 1线程、确定性算法、禁用 TF32，初始化 CUDA 前设置 `CUBLAS_WORKSPACE_CONFIG=:4096:8`。计时使用 perf_counter；CUDA 测量边界同步。暖机不计入正式重复，原始耗时全部保留，p50/p95仅作本机描述；桌面后台负载和设备执行顺序均可能影响结果。

## 固定探测工作量

1. 完整候选评分：真实玩家观测及全部合法动作（含已登记 8769 候选构造手牌），chunk256，不删候选。计时包括 Python 特征编码、tensor 构建、主机到设备传输、评分、返回 CPU。CPU/CUDA 同参数结果须 allclose(atol=1e-5, rtol=1e-4)。记录 argmax 一致性，不把浮点近似视为跨设备逐位恢复保证。
2. 更新：用真实完整对局采集的状态/动作/团队终局回报，batch64/256/1024。不足的固定数据循环填充，只作吞吐，不增加独立对局数。计时包括 CPU tensor 到设备的传输、forward/backward/Adam；要求 loss/梯度/参数有限且参数变化。每项暖机后重复20次。
3. 端到端：CPU 与 CUDA 分别从相同初始化开始，开发 seed102000..102003，级牌2/5/10/14，epsilon0.1、学习率0.001、batch64、chunk256，每局结束执行一次轨迹遍历更新，含完整研究回放校验。记录枚举、评分、更新、回放和总墙钟；不要求跨设备训练轨迹一致，不产生可晋级候选。
4. CPU 采样并行探测：固定模型、8份开发发牌，单进程和 spawn 2/4进程。模型参数固定、每手独立策略随机种子，逐手终局摘要、动作摘要、样本数必须相同。报告含进程启动的冷墙钟及各任务内部时间。它只验证静态采样一致性，不等于在线参数同步、持久进程池、训练恢复或故障回收验收。

策略函数只接收 PlayerObservation 与完整 Action 列表；发牌seed、完整状态和回放由采样管理器持有。保留测试集9000000..9009999与验证集不参与。本包无需胜率统计。

## 证据、失败与验收

输出目录必须不存在。执行前写 preregistration.json，绑定日程、配置及源文件SHA-256；保存源码ZIP、原始测量、逐阶段进度。执行后比较源码哈希；异常写 failure.json，不能产出成功结论。总控另行复算原始分位数、对局数量、一致性、ZIP/源哈希、历史P1/P2/P3a受保护清单，并执行原回归测试。

最小交付：独立运行入口、直接依赖和完整安装版本锁定、实测报告、独立复核收据、STATUS/README更新。源码/协议用相对路径；本机解释器路径仅作为运行证据。采用 reproducibility-skill 的种子、依赖、入口和结果追踪检查；本项目沿用已有 artifacts/evaluations 证据布局，没有论文或提交包。本轮不搬移历史产物。

验收成功后状态为 `ACCEPTED_RUNTIME_PROBE_V1`。下一包 P3b2 才验证持续多进程采样、轮次参数同步、训练/恢复与故障边界，之后冻结正式训练预算和独立评测晋级协议。不得仅据微基准就预估长期训练收益。
