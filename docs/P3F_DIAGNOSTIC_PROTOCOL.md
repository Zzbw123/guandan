# P3f 前置诊断协议

2026-09-26，总控在诊断前冻结。只使用开发数据，不开启新验证或保留测试。

1. 从P3e六个开发评测牌谱重建玩家观测；每个模型选择全部一次出完机会，以及按磁盘顺序最先128个其他多候选决策。对所选状态的完整合法候选分别用CUDA score_many（chunk1024和37）及直接model.forward评分。记录全量分数、选择、Greedy偏好、饱和、可出完动作排名及编码冲突。误差阈值1e-6；argmax差异若属于2e-6以内的近同分须明确记录，不宣称逐位一致。非同分选择不一致或出完/非出完编码冲突阻断后续实验。轨迹不跨入模型接口。
2. 用开发seed108500..108503，初始化314380、现有默认GPU配置，实际运行一批4手。环境记录每个玩家可见(state,action)及其所属队伍的最终±1回报；在实际训练forward/MSE调用处核对全部输入与标签多重集，并核对实际反向梯度等于2*(prediction-target)/batch_size。记录失败和CUDA证据。该模型仅供训练目标诊断，不是评测候选。
3. 检查当前P3e交付回执的实验文件hash；README/STATUS等活文档只核对P3e验收当时的冻结证据，不把后续状态更新当成原实验源码漂移。

诊断通过只表示在检查状态/本机运行中未发现上述缺陷，不证明全局编码充分性、最优行为或棋力。之后另行冻结单一训练条件、资源预算、多个初始化与新验证日程；不在诊断中根据胜率调参。
