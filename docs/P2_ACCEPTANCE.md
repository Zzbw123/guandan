## 总控设计与审查

总控在运行前写入 `P2_PROTOCOL.md`、`p2-validation.json` 和 seed-splits.json，固定 27 场景、130 原始发牌、46,800 变体对局、5,000 次分层组 bootstrap，以及唯一主要比较 `team|team|greedy`。

三名 GPT-6 Sol/high 子代理按明确文件边界实现调度/执行器、统计模块和独立黑盒测试。总控实现配置验证、并行编排、报告与原始记录审计，独立检查全部模块，要求修正统计记录的严格字段与类型检查；还补测 JSON 数字键在磁盘往返时的规范化、主要区间阈值以及乱序完成的结果摘要一致性。

## 统计解释与边界

独立单位为 130 个原始发牌组；每组包含 8 或 16 个相关变体。级牌是固定配额层，每层 10 组，bootstrap 保持此配比。总体目标是在该规则、均匀级牌配比及当前冻结基线下的单副牌表现。

全矩阵使用相同发牌，场景之间也相关。`A+B` 与 `B+A` 在完整位置互换后代表同一队伍构成，不是两份独立证据；同策略对自身的对称设计可能产生精确 50% 和退化区间，这体现调度配对，不能宣称总体不存在不确定性。

只对预先指定的主要比较作相对 50% 的判断，次要场景完整描述，不进行事后筛选或未经校正的多重显著性排名。没有追加牌局追求显著，没有更改策略以迎合本轮结果。未启动保留测试集，未晋级任何学习模型。

P2 `decision_ms` 仅含策略选牌；枚举耗时独立记录，不能与 P1 包含枚举的同名字段直接混比。超时是调用返回后判定的软时限；本阶段没有声称可强制结束任意挂死的第三方模型。

## 复现

```powershell
python scripts/validate.py
python scripts/evaluate.py --config configs/evaluation/p2-validation.json --output artifacts/evaluations/p2-validation-rerun
python scripts/evaluate.py --audit artifacts/evaluations/p2-validation-rerun
```

输出目录必须不存在，避免覆盖已有结果。原始测量以 gzip 保存，不影响重新计算精确样本分位数。审计要求当前源文件与事前记录一致；代码已改动时应使用保存的相应版本，不绕过哈希检查。
